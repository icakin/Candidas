# reports/ — what is tracked, and what deliberately is not

The C1 and C2 work produced three kinds of artefact: the reports themselves, the
tools that computed their numbers, and whole regenerated results trees. Only the
first two are tracked. This file records the split so the absence of the third
is a decision on the record rather than something that looks like an oversight.

## Tracked

| path | what it is |
|---|---|
| `REPRODUCTION.md` | C1: end-to-end reproduction of the committed results |
| `N0_SENSITIVITY.md` | C2: the three-arm treatment of the N0 back-projection |
| `RUNBOOK.md` | from-scratch instructions, per stage |
| `n0/` | the C2 report as Quarto source + rendered PDF and DOCX |
| `C11_scale_free/` | C11: the CUE optimum without the absolute scale |
| `MANUSCRIPT_FIGURE_LINKAGE.md` | C9/C10/C13: the figure-sourcing record |
| `tools/` | every script that produced a number in the reports, and its JSON/CSV output |
| `figures_N0/` | the two figures `n0/n0_report.qmd` actually embeds |
| `review_figures/` | two figures from the review round |

## Not tracked, and why

**`runs/` — the regenerated results trees.** C1 and C2 wrote four complete
results trees: `runs/C1_reproduction/` and `runs/C2_arm_{current,nobp,ramp}/`,
about 40 files each of tables plus per-arm figures. They are large and
non-canonical: the canonical results live in `results/`, and these are
alternative-treatment renderings of them.

Establishing that nothing needs them was done by parsing rather than by
assumption. The reports are **static**: `n0/n0_report.qmd` contains **zero**
executable chunks and no `read_csv`, `read.csv`, `fromJSON` or `include`;
`REPRODUCTION.md`, `N0_SENSITIVITY.md` and `RUNBOOK.md` are Markdown with their
numbers already written in. Every `runs/…` string in them is narrative — "this
was written to …" — not a render-time read. The only file dependencies of any
report are two images, and those are tracked (below).

So there are no run tables to carry across. Had there been, the policy would
have been to track those text tables and exclude the figures and `.rds`.

**Nine of the eleven `figures_N0/` PNGs** (~7.5 MB): the per-arm
`FIG1_decoupling_*`, `FIG2_the_bill_*` and `FIG_MODEL_*` renderings. Not
referenced by name in any report, and they are renderings of the `runs/` arm
trees, so they fall under the same policy. The two that `n0_report.qmd` embeds —
`c2_arm_comparison.png` and `c2_transient_diagnostics.png` — are tracked.

**`tools/c2_Tinternal.csv`** (4.9 MB): the extracted internal-temperature trace.
It is an intermediate data extract, not a result, and it is regenerated by
`tools/c2_extract_Tinternal.R`, which is tracked. Everything else under `tools/`
is kept, including every JSON the reports cite.

## Rebuilding what is not tracked

```bash
# the internal-temperature extract
Rscript reports/tools/c2_extract_Tinternal.R

# the three N0 arms and their figures (slow: three full pipeline runs)
#   see N0_SENSITIVITY.md for the CANDIDAS_N0_MODE settings each arm used
```

Note that the run trees were produced before the script renumbering; the arm
mechanism they used is described in `N0_SENSITIVITY.md`, and `15_n0_treatment_panel.R`
is the maintained successor for the three-treatment comparison.
